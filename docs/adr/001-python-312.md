# ADR 001: Bajar Python de 3.15 a 3.12 y fijar pandas < 3

- **Estado:** aceptada (2026-11-08). **Revierte** la elección inicial de Python 3.15.
- **Relacionadas:** [ADR 000](000-stack.md).

## Contexto

El repositorio nació con Python 3.15 fijado en tres lugares: `.python-version`, `requires-python` en `pyproject.toml` y el paso de instalación del CI. Era la versión más reciente y funcionó bien mientras solo usamos pandas, scikit-learn y LightGBM.

Al agregar Evidently para el reporte de drift (`uv add evidently`) aparecieron dos problemas independientes:

1. **`pyyaml` no tiene una versión ya compilada para Python 3.15 en Windows.** `uv` intentó compilarla y falló con `Microsoft Visual C++ 14.0 or greater is required`. En Windows no hay compilador de C++ por defecto, así que cualquier compañero con Windows tendría el mismo error. Además, `pyyaml` llega por Evidently y por `uvicorn[standard]`, y MLflow y Prefect traen cadenas de dependencias igual de largas.
2. **Evidently 0.7.23 no se puede importar con pandas 3.** Con pandas 3.1 falla con `ImportError: cannot import name 'infer_dtype_from_object' from 'pandas.core.dtypes.common'`. Con pandas 2.3 funciona. Es la última versión publicada de Evidently, así que no había una versión más nueva que lo arreglara. El proyecto declaraba `pandas>=3.1.0`.

El segundo problema era peor que el primero: `uv add evidently` termina bien en cuanto se resuelve el primero, y el fallo aparece después, al importar. Se detectó probando el import en un entorno aparte antes de escribir el código del monitoreo.

## Decisión

- Usar **Python 3.12** en `.python-version`, `requires-python` y el CI.
- Fijar **`pandas>=2.2,<3`** en `pyproject.toml`, con un comentario que explica el motivo.
- Regenerar `uv.lock`.

## Alternativas consideradas

- **Instalar las Build Tools de Microsoft** en cada computador con Windows: pesan varios GB, solo arreglan el primer problema y exigen un paso manual que no aparece en el README. Descartada.
- **Quedarse en Python 3.15 y no usar Evidently, calculando el drift a mano:** quita la herramienta que enseña el curso y la rúbrica penaliza un drift inventado con numpy. Descartada.
- **Python 3.13:** también compatible, pero 3.12 es la versión con más soporte de ruedas precompiladas en el ecosistema y no ofrece nada que necesitemos de 3.13. Elegida 3.12 por prudencia.
- **Quedarse con pandas 3 y esperar a Evidently:** sin fecha conocida de soporte. Descartada.

## Consecuencias

- **Costo medido:** el cambio fueron cuatro archivos (`.python-version`, `pyproject.toml`, `uv.lock`, `ci.yml`) y no tocó código propio. Las pruebas existentes pasaron con Python 3.12 y también con pandas 2.3, con los mismos resultados numéricos (por ejemplo, sensibilidad de la línea base de 0,641 en validación).
- Cada persona que traiga el cambio debe correr `uv sync`, que recrea el `.venv` (unos minutos). En Windows, si dice que un archivo está en uso, hay que cerrar VS Code y repetir.
- Se pierden las novedades de pandas 3 (por ejemplo, el tipo de texto por defecto). El código no las usaba.
- **Condición para revisar esta decisión:** cuando Evidently publique soporte para pandas 3. Entonces se puede volver a `pandas>=3` si las pruebas y el smoke pasan. `make smoke` ya avisa si alguien instala pandas 3 por accidente.

## Qué aprendimos

- Elegir la versión más reciente de Python tiene un costo que no se ve hasta que se agregan dependencias nuevas: las librerías tardan en publicar versiones compiladas.
- Conviene **probar que una dependencia se importa** y no solo que se instala, antes de construir encima de ella.
- Para decisiones que afectan al equipo entero (como la versión de Python), conviene avisar antes de subirlas: se avisó por el chat del grupo y el cambio se subió en un PR aparte.
